# 批量图片转换工具 — 设计规范

日期：2026-08-11
状态：已确认（用户批准方案，参数已定：目标 50KB / 最长边 240px）

## 1. 目标

一个**纯本地、零联网**的批量图片转换工具：

- 输入：单张图片或整个文件夹（含子文件夹）的所有图片，支持拖拽导入
- 输出：所有图片统一到 **50 KB（±2%）**、**统一宽高比例**（默认 1:1 正方形，可配置 4:3 / 3:2 / 16:9 / 自定义）、**最长边 240px**
- 比例裁剪规则：原图过宽 → 居中裁左右；原图过高 → 裁上下，**上方裁掉 30%、下方裁掉 70%（上:下 = 3:7）**
- 文件名保持不变（仅扩展名随输出格式变化）
- 在 1.5×1.5 cm 小屏幕（如 0.96"~1.28" 屏）上显示清晰
- 清晰度不足（源图小于目标）的图像 → 高质量上采样 + 锐化 + 自动对比度增强
- 清晰度过高（源图远大于目标）的图像 → 高质量压缩
- 输出格式支持 JPEG / JPG / PNG，可选手动指定或保持原格式
- 批量导出为 ZIP 包，也可单张下载
- 支持 Windows / Linux / Android 桌面与移动浏览器
- UI 首帧立即渲染，处理引擎在首帧后后台初始化（转换前就绪）

## 2. 形态与技术选型

**单文件 `index.html`**：内嵌全部 HTML/CSS/JS，`file://` 双击即开，任何现代浏览器（Chrome/Edge/Firefox/Android 浏览器）均可运行。不引入任何外部库、不发起任何网络请求（代码中无 fetch/XHR/外链资源）。

依赖全部为浏览器原生能力：

| 能力 | 用途 |
|---|---|
| `createImageBitmap`（含 `imageOrientation:'from-image'`） | 高速解码 + 自动处理 EXIF 方向；fallback 到 `Image` 元素（覆盖 SVG 等） |
| `canvas` + `imageSmoothingQuality:'high'` | 高质量缩放（lanczos/双三次） |
| 自写 unsharp mask 卷积 + 直方图自动对比度 | 低清图像增强 |
| `canvas.toBlob` + 质量二分搜索 | JPEG 编码并精确命中目标字节大小（±2%） |
| 自写 PNG 编码器（`CompressionStream('deflate')` = zlib） | PNG 无损编码，含 RGB 直通与调色板量化两档 |
| 自写 ZIP 生成器（`CompressionStream('deflate-raw')`） | 批量导出 ZIP（ZIP 需要 raw deflate） |
| 自写 CRC32（查表法） | PNG chunk 与 ZIP 校验 |
| `<input webkitdirectory>` + `webkitGetAsEntry` 递归遍历 | 文件夹导入（Chrome/Edge/Android/Firefox 支持） |
| 拖放 API | 拖入单图/文件夹 |
| `localStorage` | 记忆设置（try/catch 兜底） |

线程模型：主线程 + 每张图之间 `await` 让出（`setTimeout(0)`），保持进度条与取消按钮响应。240px 小图处理极快，无需 Web Worker（Worker 在 `file://` 下兼容性风险大，收益低）。

## 3. UI 结构（中文、响应式）

- **头部**：标题 + "纯本地 · 不上传任何数据" 角标
- **导入区**：大虚线拖放区 + 「选择图片」/「选择文件夹」按钮
- **设置面板**（折叠式，默认展开）：
  - 目标大小 KB（预设 30 / 50 / 100 + 自定义输入）
  - 输出比例（默认 1:1，可选 4:3 / 3:2 / 16:9 / 自定义 W:H）
  - 最大边长 px（预设 128 / 200 / 240 + 自定义输入）
  - 输出格式：保持原格式 / JPEG / JPG / PNG
  - 低清增强开关（默认开）
  - 误差容差（默认 ±2%，范围 1–10%）
- **文件列表**：缩略图 + 文件名 + 原大小 + 状态（等待/处理中/完成/失败）+ 结果大小 + 单张下载按钮；支持全选/移除已完成/全部清除
- **进度条** + 计数（n/m 完成）
- **导出区**：「下载 ZIP」大按钮（完成后出现）
- 移动端：单列布局、大触控目标、底部粘性操作栏；桌面端：居中卡片
- 暗色模式跟随系统（`prefers-color-scheme`）

## 4. 处理管线

每张图依次经过：

1. **解码**：`createImageBitmap`（自动 EXIF 方向）→ 失败则回退 `Image` + objectURL
2. **比例归一（裁剪）**：先在原始分辨率裁剪到目标比例（默认 1:1），保留最大信息——原图过宽 → 居中裁左右；原图过高 → 裁上下，上方裁掉多余部分的 30%、下方裁掉 70%（3:7）
3. **尺寸归一**：裁剪后最长边 → 240px。源图最长边 < 目标（清晰度不足）→ 高质量上采样；远大于目标 → 高质量下采样
4. **增强**（仅上采样时）：unsharp mask（轻度，radius 1、强度可调）→ 直方图裁剪对比度增强（2%–98% 百分位拉伸，防过曝）
5. **编码到目标大小**：
   - **JPEG/JPG**：`toBlob('image/jpeg', q)`，q 在 [30,95] 二分搜索，直到大小落在 [目标×(1−容差), 目标×(1+容差)]；q=30 仍过大 → 逐步降分辨率（最长边每步 −12%，下限 64px）重试；触及下限仍过大 → 接受当前结果并提示
   - **PNG**：先试 24bit RGB/RGBA 直通 → 若超目标，调色板量化（中位切分，颜色数 256→128→64→32→16→8→4 逐级降）→ 仍超则降分辨率；PNG 无损，承诺 **≤ 目标×1.02**（下限 64px，触底接受并提示）
5. **命名**：保留原文件名（含子文件夹相对路径），扩展名按输出格式替换

## 5. 导出

- **ZIP**：自定义生成器 —— local file header + raw deflate 数据 + central directory + EOCD，CRC32 查表校验；文件名 `converted_<时间戳>.zip`；`file://` 下通过 `a[download]` + objectURL 下载（Android 浏览器会走系统下载）
- **单张**：每行「下载」按钮
- 失败文件：不打包，列表标红并给出原因

## 6. 启动时序（快速启动）

1. HTML/CSS 与首屏静态 UI 同步渲染（引擎代码靠后定义，不阻塞首帧）
2. 首帧后（`requestAnimationFrame` + `setTimeout(0)`）：预热 —— 创建 canvas、探测 `createImageBitmap`/`CompressionStream` 可用性、初始化引擎对象、恢复 localStorage 设置
3. 用户点击转换时引擎已就绪

## 7. 错误处理

- 单文件失败不中断批处理（try/catch 每张图），状态列显示原因
- 无法解码的格式（如 HEIC）：明确提示"浏览器无法解码，请转换为 JPEG/PNG 后重试"
- 解码失败回退链：createImageBitmap → Image → 标记失败
- localStorage 写入失败静默忽略

## 8. 测试

- 纯逻辑（CRC32 / PNG 编码 / ZIP 生成）：抽出为独立 JS，用 Node（≥18，含 `CompressionStream`）跑单元冒烟测试
- 端到端：`start index.html` 打开浏览器，人工验证：单图/文件夹导入、拖拽、三格式输出、大小命中、文件名保留、ZIP 解包正确、移动端布局（DevTools 模拟）

## 9. 安全性与独立性（用户强约束）

- **0 环境依赖 / 运行环境独立**：交付物 = 单个 `index.html`，双击即用；无安装、无 Node/Python/浏览器插件、无后台进程
- **防危害用户机器**：运行在浏览器沙箱内——页面无法读写用户文件系统（只能读取用户主动拖入/选择的文件）、无法执行系统命令；这是比任何安装包更安全的形式
- **零联网**：无 fetch/XHR/WebSocket/外链资源；`build.js` 打包时静态检查，发现即构建失败
- **注入防护**：所有用户文本（文件名等）以 `textContent` 渲染，禁止 `innerHTML` 拼接；无 `eval` / `new Function`；build 静态检查强制
- **zip-slip 防护**：ZIP 条目名去除盘符、前导斜杠与 `..` 片段，防解压路径穿越
- **错误隔离**：单图失败不中断批处理；超大图解码失败给出友好提示
- **隐私**：处理全程在本机内存完成，图片不出设备
